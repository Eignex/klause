# 14.2 Finite propagation

After a decision is applied, search runs the finite-domain fixpoint: every
propagator narrows the Boolean and integer domains it watches until nothing changes
or a conflict appears. This subchapter describes who owns that state, how the
propagation projection for each factor is selected, how propagation feeds the
branching heuristics, and which checks a complete finite point must pass before it
can be published. The reasons propagators record for their deductions are the
subject of the [next subchapter](14.3-learning.md).

## Finite propagation

[PropagationSession](../klause/src/commonMain/kotlin/com/eignex/klause/propagation/PropagationSession.kt)
owns the finite-domain trail and fixpoint. Sessions over one immutable model can share
built-in stateless propagation projections and occurrence indexes. Incremental
payloads, scratch arrays, watchers and failure contexts belong to each state. Failure
clauses and premise-variable sets use separate state storage, leaving reversible
payloads intact; each fire clears its previous failure, and undo discards pending
failure context. Fresh presolve rebuilds retain the originating cancellation token and
accounting destination; see [presolve](12-presolve.md).

Boolean-only models journal each pin's variable id and tag without integer-state
padding. Mixed finite models retain aligned integer-state columns for domain
retraction. Integer undo replays complete saved domains and interior carves through a
typed restoration phase. Unconditional interior carves made at the root retain their
membership in state-owned interval runs, so late equality atoms and historical queries
still see them; conditional carves retain ordered records and undo prefixes.

Variable-array Element groups unsupported result and selected-cell values sharing one
premise into a single immutable domain replacement. The mutation retains individual
hole reasons and all changed bound, value and fixed-variable wakeups; one trail record
restores the complete prior domain.

One completed CP fixpoint's integer publication callback shares Boolean- and
root-grounded native subproofs with search peers. The memo holds at most 4,096 literal
entries and each export retains its 4,096-frame visit guard. No memo survives a
callback, iterator suspension or retraction; published premise conjunctions own their
lists and outlive the scratch state.

### Arithmetic kernels

Several propagators guard signed-word arithmetic explicitly rather than wrapping:

- Strict increasing chains reject an endpoint that needs a successor above
  `Long.MAX_VALUE` or a predecessor below `Long.MIN_VALUE`.
- Product bounds clamp corner products to signed-word endpoints. Repeated operands
  use nonnegative square bounds and exact integer square-root inverse bounds.
- Integer `Power` uses exact signed-word comparisons for forward and inverse bounds,
  preserving sign and both even roots. Each fire filters at most 256 present input and
  output values; wider domains retain bounds filtering and exact pinned checks.
- Lexicographic comparisons with an empty common prefix use the vector-length
  tie-break; a length-only conflict has no domain premises.

Mixed-sign input domains retain their interior values, and complete assignment
checks still enforce the complete relation.

### Difference systems

The finite difference system is posted after presolve only when its fragment has a
guarded edge and an edge between two unfixed root integer columns. Edges to zero or
root-fixed columns act as unary bounds and retain their original propagators.

Finite preparation can also append a redundant difference system over exact real
rows and real table selections. Its vertices are private arithmetic coordinates;
they create no finite real domains. Supported source Boolean guards enter the graph
directly, and each table index equality is resolved to a native integer atom, so a
contradictory selection can be excluded before all discrete columns are fixed. Cycle
and path explanations contain the active source guards and native index premises. A
consistent graph supplies no model or completed leaf; all original factors, source
witness checks and required LP completion remain. See
[real graph admission](19-difference.md#real-graph-admission-and-checks).

## Selected propagation projections

`PropagationProjectionProvider` selects a source-bound factory and its filtering and
pinned-assignment-check capabilities during preparation. Engine projection creation
rejects a factory whose `NoPropagator` result disagrees with its declared inert role,
and an unsupported role refuses construction. Alternative deductions must remain
sound for the original factor, including watcher subscriptions and explanations.
`SOUND_FILTERING`, `BOUNDS_FILTERING` and `DOMAIN_FILTERING` describe deduction
mechanisms; they do not promise full consistency at every size or resource limit.

Exact integer source rows select compact signed-word propagation when their cleared
constants fit and the sum of coefficient magnitudes is at most `Long.MAX_VALUE`,
which keeps activity and residual checks within signed 128 bits. Reified comparisons
at either signed-word endpoint, and rows with wider constants, retain
arbitrary-precision propagation. The original exact row and source witness checks
remain authoritative.

Packed SAT propagation requires built-in selected clause descriptors. A clause
assigned to a custom CP projection is omitted from the shared default clause
propagator and uses the general CP lane, so native propagation cannot bypass it.
AllDifferent filtering selects its cached incremental path before the full matching
fallback. Shared table preparation transfers no-op verdicts only under matching
contiguous column domains; MDD preparation sharing includes the initial and accepting
states. Reversible live tuples, diagram reachability and all assignment-dependent
payloads remain state-owned.

An inert descriptor requires an explicit reason and cannot claim an exact check: its
absent mechanism needs an enforcing peer or separate source certification. Gaussian
XOR and difference-system helpers omit local-search scoring because their retained
source rows enforce the assignment; symmetry helpers omit it because source witnesses
need not satisfy a chosen CP representative. Objective-bound overlays omit CP
propagation. A sound LP family can decline emission under feature, resource or domain
gates; omitted rows only weaken the relaxation.

Source preparation retains captured factor projection descriptors when selecting open
ownership and optimization rounds, and domain closure retargets them without changing
coordinate ownership. A factor rewrite reselects providers before constructing the
compact CP view. Polynomial and quadratic workers retain the same descriptors when
opening their private finite projection. A selected finite relaxation is a sound
bounding view, never source-completion authority.

## Branching and global deductions

Finite branching receives the native conflict's full variable and factor attribution,
including implication-graph variables for learned conflicts. VSIDS bumps each
implicated variable once per conflict, including a failed decision already in that set;
CHB applies one conflict reward to each attributed variable. Conflicts cascading from a
native learned assertion also update activity and failure counters. Successful CP
fixpoints deliver newly reported deductions to propagation-aware selectors in both
satisfaction and optimization search. Phase saving captures determined values before
native trail retraction, retaining propagated polarities as well as decision
polarities across backjumps and restarts.

Dom/wdeg initializes from the session's prepared occurrence indexes. Failure weights
and its heap belong to the solve and retain conflict bumps across restarts. Fresh
selectors isolate solves that share a projection.

General CP optimization builds its private state in retained batches before
traversal. The projection owns completed occurrence indexes; the state owns domains,
literal/event watchers, payload slots and its root queue. Assumption installation
retains each pending decision and fixpoint until it commits its trail mark, and shared
component publication is batched after those assumptions reach a complete fixpoint.
Closing or failing installation releases that cursor without exposing partial state.
The [portfolio contract](16.2-portfolio-scheduling.md#private-cp-preparation) defines handoff and
[resources](11-resources.md) define the accounting boundary.

Cumulative edge-finding runs in both time directions over fixed durations, demands and
capacity. Reversed deductions tighten latest starts and cite the historical integer
bounds and definitely-present task premises. Arithmetic ranges that cannot be
represented safely decline the reversed pass.

## Complete finite checks

Complete finite checks pin the full assignment and run a completed CP fixpoint. They
stop after an interrupted root or before further coordinate pins when their
cancellation token expires; interrupted verification remains indeterminate.
Local-search invariant satisfaction is a separate check from its graded score, and a
zero heuristic score is not an exact certificate.

Selected partial or inert finite deduction keeps an original-source check at a
complete point. The prepared check plan is immutable; each point uses a private
propagation state over original factors, and its work contributes to the invocation's
CP counters. If those factors have no complete original checker, the leaf stays
indeterminate. Source-real checks remain the arithmetic completion's responsibility;
objective overlays remain enforced by objective policy.

### Custom factor publication checks

Custom factors retain the `Propagator` and `Invariant` extension paths. A custom
`Propagator` without an `Invariant` maps to `NoInvariant`, which contributes no
local violation. Before publishing a zero-score candidate, standalone LS and its
ALNS consumers pin every Boolean and integer coordinate in a private propagation
state containing the uncovered constraints. A completed full-assignment fixpoint
checks the candidate; root consistency alone does not. Custom propagators must
reject invalid complete assignments, as required by their CP execution path.
Constraints requiring continuous coordinates without an exact local checker
explicitly decline finite local-search execution.

Rejection applies only to the candidate. Interrupted checking withholds publication
without refuting the source or its assumptions. Caller completion runs after the
uncovered finite checks and retains responsibility for exact arithmetic completion;
replacement or cancellation withholds the witness. A custom `Invariant` supplies local
checking and scoring but no CP propagator. Structural-only custom factors refuse CP
and local-search execution with route-specific errors. Custom implied linear rows
remain available to LP relaxation independently of either execution interface.
