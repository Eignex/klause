# Linear real arithmetic

Linear real constraints combine real coordinates with constant coefficients and
Boolean structure. Exact rational checks decide the active linear system; shared
search explores Boolean or arithmetic alternatives. Strict inequalities require
an interior point, rather than a point on the closure's boundary.

This theory follows the [shared theory contract](../theories.md). Integer
integrality belongs to [linear integer](linear-integer.md) or
[linear mixed](linear-mixed.md) arithmetic.

## Scope and boundaries

The pure-real route requires real variables, no source integer variables, and
factors wholly represented by admitted exact linear forms. Source bounds,
reification, disjunction and strictness remain authoritative. Nonconstant real
products belong to [polynomial real arithmetic](polynomial-real.md).

[Difference logic](difference.md) supplies a graph mechanism for an admitted
pure-real subfragment. General linear rows retain the LP-backed route; a graph
admission decline does not itself reject a supported linear source.

## Solving and composition

Shared decisions activate rows and comparisons. The arithmetic component retains
those assertions through their decision scope, checks the residual system and
contributes exact source coordinates at a complete check. Disequalities require
an applicable direction and remain part of the source check.

Resolved original pure-real rows can also conflict through exact equality
elimination before numerical completion. Literal opposite non-strict rows establish
equalities; Gaussian substitution can prove an inconsistent equality or reduce an
active inequality to a false constant. A completed derivation can retain the actual
input rows used by its equality pairs and nonzero pivot eliminations. Both opposite
inequalities justify an equality; a refuted residual also requires its own row.
These supports can omit unrelated source guards, but need not be minimum cores.

alternatives, unavailable explanations and interrupted or oversized arithmetic

## Results and proof authority

`ExactLraAssignment` captures Boolean values and rational real coordinates.
Completed source checks admit witnesses. Exact conflicts, bounds and rays follow
[LP certification](../lp/certification.md); a floating status alone is insufficient.
Strict infeasibility requires a completed strict-feasibility check, not failure to
find a positive margin within a budget.

Open real objectives with complete affine source capture use `RationalTheoryDescent`'s
retained linear authority invocation. Shared Boolean traversal, exact source bounds,
attained witnesses, strict approach paths and feasible improving rays determine its
result. `OpenTheoryOptimum.linearResult` retains original-direction evidence and
separates the incumbent value from an unattained limit. A limit is not an attained
optimum. Unsupported source capture retains the theory's strict-improvement route;
incomplete optimization withholds global claims and preserves checked incumbents.
[LP certification](../lp/certification.md) defines the affine authority checks.
[Input semantics](../formats.md) defines each frontend's exact or tolerance policy.

## State and resources

Immutable row addresses, forms and Boolean dependencies can be shared by fresh
components over one canonical immutable fragment. `prepareExactLiraSource` returns
an opaque factory only after complete, uncancelled preparation; its openings retain
the public component's source semantics. The direct constructor still prepares its
own rows. Scoped assertions, graph potentials, LP bases and witness candidates
remain invocation-owned. Retraction restores their premises and invalidates
incompatible evidence. Open work and numerical limits retain their own currencies;
a stopped source check withholds the witness or proof.

An owned exact LP point can also remain feasible after a Boolean pin in the same
pure-real LP scope. Newly resolved comparisons are checked exactly against that
point after their actual LP assertions and premises are installed. Bounded scalar
checks use the current operation token; an incompatible or declined comparison
retains ordinary LP solving. The containing check allowance is still consumed.
This reuse excludes graph openings, private real completion coordinates, source
disjunctions, private arithmetic branches and disequality direction state. Retraction discards the point; a same-level restart also discards reuse eligibility
until a fresh LP result supplies an exact point.
Reusing a partial point supplies no source verdict; a complete Boolean leaf still
passes the original source-coordinate checks. Source equality refutation retains
its earlier conflict check and actual premise validation before a retained point
can skip numerical solving.

Sources with no numeric coordinates or no Booleans retain traversal without this
optional hint work. Integer-only registration is limited to the default-null
primitive path; explicit allowances retain their existing producer admission.
Optional hint storage admits at most 65,536 source
row/term/coordinate/index entries.
The scalar policy admits 4,096-bit normalized rationals and bounds intermediate
products before evaluation. Copying, term visits and bit/word arithmetic costs
charge the current operation token's native meter and poll its unchanged deadline.
No LP or graph invocation, complete-check charge or allowance is created for hints.
Default graph suppression retains registration and all capture work already spent.
Release occurs only after a live consultation passes the existing availability and
containing-stop checks. It prevents subsequent optional captures without changing the
source candidate or arithmetic state. Unavailable points and caller-preempted
consultations can retain capture costs until release or close.
Publication is transactional; a cancelled scan publishes nothing. Arithmetic
decisions, retraction and restart invalidate preferences. A Boolean decision absent
from all arithmetic dependencies can retain the same point preferences in its
unchanged arithmetic residual. Closing releases the primitive and clause indices.
Opt-in partial-point hints first complete a raw original-clause incidence core before
optional compound recognition spends the remaining shared index allowance. Raw
polarity scoring uses registered primitive comparisons and current pins; every
unrecognized Boolean partner remains unknown. No gate meaning is derived without
a completed global profile. Full recognition retains ambiguity and acyclic checks
and excludes only qualified definition clauses from scoring. Failed optional profiles
leave the completed raw core intact; a failed raw core can retain direct primitive
preferences only after complete ID validation. Source invalidity and containing stops
withhold all optional preferences. Retraction, dirty state, coordinate limits and
close retain their point authority; no index limit renews numerical work.
Hint applicability observations distinguish an initially unavailable point, an
uncovered selected Boolean and a primitive callback returning no preference.
They do not distinguish unavailable point state, scalar admission or an individual
guard's row decline, and they perform no additional producer or owner calls.
Separate exact-linear observations count completed graph-first openings, completed
primitive table captures from graph and LP points, and live default consultations
that release graph-first hints. A capture identifies its actual producing path;
graph-first admission alone does not identify a later fallback point. These counts
reuse completed branch outcomes without additional checks, polls or charges. They
measure neither elapsed cost nor witness validity, and a completed table can contain
only declined preferences.
