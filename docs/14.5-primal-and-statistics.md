# 14.5 Primal heuristics and statistics

Complete search proves results, but it can also find good incumbents early. This
subchapter describes the two primal heuristics that run inside complete search, the
root LP proposals on mixed models and the monotone clausal probe on pure-Boolean
optimization, and closes with the counters search reports. Neither heuristic carries
proof authority: every proposal passes full source verification before it becomes an
incumbent.

## Root primal proposals

On mixed models, the root LP relaxation also proposes incumbents. Nearest rounding,
directed upward and downward rounding of the retained LP point, a peer worker's
discrete assignment and a feasibility pump each produce discrete targets. Every
distinct proposal passes the discrete fixpoint under the caller's assumptions, then
real completion through the real-leaf owner or the caller's source tolerance check,
then full source verification. Only a complete checked witness reaches incumbent
admission, and every producer must strictly improve the current cutoff there; exact
source objectives govern that comparison when available. An integral distance optimum
with no fractional support uses seeded perturbations of the live discrete coordinates
to escape. Fixed coordinates remain fixed.

The opt-in `lbTreeSearch` probe extends this to a private finite trail with exhaustive
fractional and value alternatives, trying the nearer side of the LP value first. It
returns accepted witnesses only and exports no optimum, refutation, bound or recession
claim. The `lp-lbtree` portfolio recipe can enable it.

Root primal solves, probe LP assembly, edits and decisions charge the containing root
ledger and solve-wide `NodeBudget`, not the adaptive node-query allowance. A
primal/dual fallback opens a fresh solve with the remaining allowance without renewing
it. Private numerical owners close on return, interruption and exception.

## Monotone clausal primal probe

Pure Boolean clausal optimization with at most 64 positive-cost variables can seed
incumbents through greedy feasibility repairs when those variables occur only
positively in hard clauses. The probe runs once before ordinary optimization and is
skipped behind an existing shared incumbent or within repair fragments.

A private satisfaction repair first obtains a feasible assignment with unaccepted cost
variables true; caller and baked-root pins form its stable scope. Free true values then
become false wherever that single change preserves every hard clause. Trials try to
turn off the remaining cost variables in descending weight order through a clause walk
that changes only free variables, raises clause penalties when no move improves the
weighted violation, and restores the previous feasible assignment on failure. Only
feasible trials retain their cheaper cost assumptions, and clause-local polishing
removes unnecessary costly values.

Each private satisfaction trial runs on a projected model: unit propagation removes
fixed literals and satisfied clauses, two bounded Boolean elimination passes reuse the
presolve mechanism, and surviving variables receive dense private coordinates. Lifting
applies the elimination records in reverse. Private satisfaction uses the SAT preset
with inprocessing disabled. Private infeasible verdicts contribute no outer proof, and
the composed verifier checks the full original proposal before publication.

All probe work is charged to the owning arm, and moves spend the solve-wide move
allowance. The complete probe receives at most half the remaining solve allowance in
active execution time, capped at 5 seconds; polishing and verification each have a
100 ms cap within the whole-solve deadline. Search counters distinguish probe starts,
trial starts, returned models, improving proposals and installed incumbents, and
separate private refutations from incomplete stops.

## Statistics

Search reports what its traversal observed; counters are observations, not proofs.

| Field | Meaning |
|---|---|
| `propagations` | Finite Boolean, singleton, bound, hole and survivor-set deductions reported by completed search fixpoints; excludes decision and root pins |
| `learned` | Learned consequences observed by the traversal, including native CP learning |
| `caNotApplicable`, `caNonAsserting` | Native CP analyses declining a usable or asserting consequence; exported by every CLI format |
| `propagationWork` | Monotonic dispatch, literal, watcher, level and linear-term/reason visits, including work across undo |
| `rootPropagationWork`, `rootPropagationMs` | Initialization root-fixpoint work and time, including private preparation |
| `propagationMs` | Fixpoint elapsed time; some counted reason scans are outside it |
| `openAssertingConflicts` | Shared first-UIP analyses yielding an asserting backjump |
| `openNonAssertingConflicts` | Sound shared conflicts retaining chronological fallback |
| `openReductionNs` | Total shared reduction selection and watch-rebuild time; zero when the cap is off |

A nonzero non-asserting count points at a component reason that did not support
first-UIP learning. Zero does not establish complete factor reason coverage. Missing
metrics remain missing, including root theory refutations that never enter shared
search.

The CLI exports native work and time under `nativeCpPropagationWork`,
`nativeCpRootPropagationWork`, `nativeCpPropagationMs` and `nativeCpRootPropagationMs`
when the aggregate snapshot has positive native work or time. Root work and time are
subsets of the respective totals, not additive phases, and worker snapshots aggregate
their measurements rather than partitioning invocation wall time. The
[CLI invocation fields](31-cli.md) distinguish frontend routing, selected solve
pipeline, declared theory and reported backend.

Complete open-theory search adds `smtCompleteSearch*` observations: the compiled
Boolean count and smallest observed number of unassigned Booleans, LP checks and
returned points with all Booleans assigned, returned verdicts, and stage counters
along the branch, mixed point recovery and polarity hint paths. They exclude private
queries and neighborhood openings, stay absent rather than zero until observed, and
overlap, so they are not a work total. None of them is a source witness.
